# Мастер-панель (Marzban) — кастомный образ

Мастер собирается из патченного `gozargah/marzban` образа — три точечных
патча upstream-кода, все задокументированы прямо в `Dockerfile`. Раньше жили
только руками на сервере; теперь версионируются здесь.

## Деплой / пересборка на сервере
```bash
scp Dockerfile docker-compose.yml root@<панель>:/opt/marzban/
ssh root@<панель> 'cd /opt/marzban && docker compose build && docker compose up -d'
```
`.env` и `/var/lib/marzban` (БД, `xray_config.json`, TLS) на сервере не трогаем —
они не в этом репозитории и не должны там быть (креды, сертификаты).

## Патчи в Dockerfile
1. **sid-fix** — подписка отдавала `sid` от неверного объекта конфига.
2. **vless encryption=none** — явный параметр в ссылке для клиентов, которым он нужен.
3. **core_health_check try/except** — рестарт локального core мастера ничем не
   обёрнут в оригинале. Мастер по архитектуре не возит трафик (порт 443 занят
   панелью/CF) — его локальный xray физически не бинднется и падает на каждой
   проверке. Без try/except исключение раньше срывало весь health-check ДО
   цикла проверки **нод**. См. `../node/TROUBLESHOOTING.md`, раздел #3.

## Отдельно, не в образе (данные, не код)

`/var/lib/marzban/xray_config.json` на сервере — bind-mount, не часть образа.
Если там когда-то появится блок `"log": {"access": "...", "error": "..."}` с
путём вида `/var/lib/marzban-node/...` — это debug-хвост с прошлой сессии,
падает мастер (путь существует только у нод, не у мастера). Смотри
`../node/TROUBLESHOOTING.md`, раздел #3, там же команда для проверки причины
краша.

## Безопасность: спрятать дашборд и путь подписки

Marzban по умолчанию отдаёт админку на `/dashboard/` и подписки на `/sub/` —
общеизвестные пути для любого сканера, и, что важнее в контексте DPI в РФ,
узнаваемый паттерн самой ссылки (даже с уникальным токеном клиента префикс
`/sub/` выдаёт «это VPN-панель»). Нода этой обфускации не требует — у неё нет
HTTP-путей вообще (голый TLS REALITY на 443), она уже защищена mTLS-cert +
IP-скоупом UFW.

```bash
bash panel/randomize_paths.sh
```
Генерирует случайные `DASHBOARD_PATH`/`XRAY_SUBSCRIPTION_PATH`, правит
`/opt/marzban/.env`, перезапускает Marzban. Идемпотентно — можно гонять
повторно для ротации (например, если старый путь где-то засветился). На
боевой базе клиентов перед повторной ротацией разошли новую ссылку заранее —
старые ссылки/букмарки после смены пути перестанут открываться.

## Безопасность: подписка мимо Cloudflare (`sub.` домен)

Реальный случай: клиенту в РФ на мобильном интернете не грузилась ссылка-подписка
(таймаут), хотя сама VPN-ссылка (raw `vless://`) работала и дашборд панели
открывался. Раскопки заняли несколько раундов гипотез (SNI-блок домена → не
подтвердился, дашборд же открывался; контент-сигнатура → технически
невозможна, TLS шифрует заголовки; паттерн трафика → тоже не подтвердился,
финальный тест показал, что у части клиентов **весь** домен, включая
дашборд, недоступен без VPN — то есть блокировка не по паттерну ответа, а по
самому домену/IP-диапазону Cloudflare для конкретных провайдеров/регионов).

Решение — увести выдачу подписки на **отдельный поддомен, не проксируемый
через Cloudflare** (DNS-only / серое облако), с настоящим Let's Encrypt
сертификатом вместо Cloudflare Origin CA (тот доверяют только клиенты,
идущие через сам CF — при прямом подключении будет ошибка сертификата).
Дашборд остаётся через CF как был.

**Архитектура:**
```
mon.logs-storage17.com  --(Cloudflare, orange)-->  Caddy:443  --> Marzban:127.0.0.1:8001
sub.logs-storage17.com  --(DNS-only, серое)----->  Caddy:443  --> Marzban:127.0.0.1:8001
```
Marzban больше не слушает публичный 443 напрямую — Caddy стоит перед ним и
термирует TLS для обоих доменов (свой сертификат на каждый: CF Origin для
`mon.`, честный Let's Encrypt для `sub.`).

**Разворот (один раз, на мастере):**
1. Завести в Cloudflare A-запись для нового поддомена (например `sub`) на IP
   мастера, **Proxy status: DNS only** — критично, иначе смысл теряется.
2. `.env` Marzban: `UVICORN_HOST="127.0.0.1"`, `UVICORN_PORT=8001`,
   закомментировать `UVICORN_SSL_CERTFILE`/`UVICORN_SSL_KEYFILE` (TLS теперь
   у Caddy, не у Marzban).
3. Поставить Caddy (`apt` через официальный репозиторий cloudsmith).
4. `caddy/Caddyfile` в этом репозитории → `/etc/caddy/Caddyfile` на сервере.
5. Получить серт для `sub.` через `certbot certonly --standalone` (порт 80
   свободен на этом шаге, Caddy ещё не запущен) — **дальнейшие продления**
   переключить на `--webroot`, иначе `certbot renew` будет конфликтовать с
   Caddy за порт 80 (см. `caddy/README.md`). Важно: в Caddyfile нужен глобальный
   `auto_https off` — иначе Caddy сам перехватывает ACME-challenge путь ДО
   вебрут-хендлера и `certbot renew` виснет/получает 404 (подробности и готовый
   Caddyfile — `caddy/README.md`, раздел «Готча»).
6. ACL: `caddy` работает не под root, дефолтный ACL на `/etc/letsencrypt/archive/sub.../`
   нужен, иначе Caddy не прочитает privkey. Подробности и готовые команды —
   `caddy/README.md`.
7. `.env` Marzban: `XRAY_SUBSCRIPTION_URL_PREFIX = "https://sub.логи-домен"`.
8. `docker compose up -d` (не `restart` — не подхватит переменные).

⚠️ **Известная гонка портов**, из-за нехватки в апстриме Marzban флага «не
поднимать инбаунды локально» (см. патч #3 выше): локальный xray мастера
тоже хочет :443 и, если освобождается раньше Caddy (например, после ребута
сервера или ручного `systemctl stop caddy`), успевает его перехватить —
Caddy тогда не стартует (`address already in use`). Лечится вручную:
```bash
ss -tlnp | grep :443          # кто держит порт
kill -9 <pid_xray>            # если это xray, не caddy
systemctl start caddy         # Caddy держит порт постоянно, xray дальше
                               # просто не может его перехватить — штатно
```
При обычной работе (без ребута/ручных рестартов Caddy) гонка не возникает —
Caddy, однажды заняв порт, не отдаёт его.

Подробный Caddyfile и инструкция по установке — `caddy/README.md`.

## Архитектура
Мастер — «мозг»: панель, БД, выдача клиентам подписок. Трафик не возит —
это делают ноды (см. `../node/`). Мастер тем не менее ВСЕГДА пытается поднять
тот же core-конфиг локально (ограничение апстрима Marzban, нет флага
«не поднимать инбаунды локально») — отсюда патч #3 выше, чтобы это не мешало
здоровью нод.
