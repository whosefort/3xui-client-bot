# 3xui-client-bot

Telegram-бот для клиентов VPN на базе [3X-UI](https://github.com/MHSanaei/3x-ui).  
Один Docker-контейнер, без входящих портов, без платёжного шлюза.

## Что умеет

**Клиент**
- `/start` — главное меню
- «Статус» — сколько дней осталось + ссылка-подписка
- «Купить» / «Продлить» — отправить заявку, показать реквизиты
- «Связаться» — написать администратору прямо из бота

**Администратор** (в Telegram)
- Подтвердить / отклонить заявку одной кнопкой → бот сам создаёт клиента в панели
- `/expiring` — кто истекает в ближайшие 7 дней
- `/grant <tg_id>` — выдать подписку вручную
- `/price <сумма>` — изменить цену
- `/requisites <текст>` — изменить реквизиты
- `/broadcast <текст>` — рассылка всем клиентам

**Автоматически**
- Напоминания о конце подписки за 3, 1 и 0 дней
- Heartbeat-сообщение администратору раз в сутки

## Первый деплой

### 1. Клонируйте репозиторий на сервер

```bash
git clone https://github.com/YOUR_USERNAME/3xui-client-bot
cd 3xui-client-bot
```

### 2. Запустите скрипт деплоя

```bash
./deploy.sh
```

Скрипт сам создаст `.env` из примера и откроет редактор.  
Заполните переменные (см. раздел «Конфигурация» ниже) — и всё.

---

## Обновление

```bash
cd 3xui-client-bot
./deploy.sh
```

Скрипт сделает `git pull`, пересоберёт образ и перезапустит контейнер.  
База данных (`data/bot.db`) при этом **не трогается**.

## Конфигурация (`.env`)

Скопируйте `.env.example` в `.env` и заполните:

```dotenv
# Telegram
BOT_TOKEN=         # токен от @BotFather
ADMIN_IDS=         # ваш Telegram ID (узнать у @userinfobot), можно несколько через запятую
SUPPORT_CHAT_ID=   # куда пересылать сообщения из «Связаться» (обычно = ваш ID)

# 3X-UI
XUI_BASE_URL=      # https://ваш-домен:порт/секретный-путь  (без /panel на конце)
XUI_AUTH=token     # оставьте token
XUI_API_TOKEN=     # API-токен из настроек панели

# Подписка
SUB_URL_TEMPLATE=  # https://ваш-домен:sub-порт/sub-путь/{subId}
DEFAULT_INBOUND_IDS=1    # ID инбаунда в панели (обычно 1)
CLIENT_FLOW=xtls-rprx-vision

# Тариф
PLAN_DAYS=30
DEFAULT_PRICE=199
DEFAULT_REQUISITES=Сбербанк 0000 0000 0000 0000 (Имя Ф.)
```

> `SUB_URL_TEMPLATE` — шаблон ссылки-подписки. Возьмите любую рабочую ссылку  
> клиента из панели (`https://домен:порт/путь/abc123xyz`), замените `abc123xyz`  
> на `{subId}`.

## Архитектура

```
Telegram ←──long-polling──→ aiogram 3.x
                                │
                         handlers/ ─┬─ user.py    (клиентские сценарии)
                                    ├─ admin.py   (управление подписками)
                                    └─ common.py  (resolve_client, notify_admins)
                                │
                            xui.py ──→ 3X-UI Clients API  (Bearer token)
                                │
                            db.py  ──→ SQLite  (users, requests, settings,
                                                reminders_log)
                                │
                         scheduler.py ──→ APScheduler  (ежедневный обход)
```

**Один контейнер, long-polling** — входящие порты не нужны, вебхуки не настраиваются.  
**SQLite** — живёт в `./data/`, монтируется томом, переживает пересборки.  
**tgId-bridge** — связь клиент↔Telegram через поле `tgId` в панели.

## Безопасность

| Что | Как защищено |
|---|---|
| `.env` с токенами | `chmod 600`, в `.gitignore` |
| `data/` с базой | `chmod 700`, в `.gitignore` |
| API-токен панели | только в `.env`, в код не попадает |
| Лимит трафика (150 ГБ) | клиенту не показывается нигде |
| Ссылки-подписки | не логируются, не показываются в публичных сообщениях |
| Доступ к админ-командам | жёсткий allowlist по `tg_id` |

## Переменные для старых клиентов

Если клиент уже есть в панели, но без `tgId`:
1. Откройте клиента в 3X-UI → укажите его Telegram ID в поле `tgId`
2. Клиент напишет боту `/start` → бот автоматически найдёт его по `tgId` и покажет статус

Новых клиентов создаёт бот сам при подтверждении заявки.
