# 3xui-client-bot

Telegram-бот, который продаёт, выдаёт и продлевает VPN-подписки — и одновременно
пульт управления всей инфраструктурой прямо из Telegram, без захода в
веб-панель для рутинных задач. Название репозитория осталось историческим
(проект начинался как обвязка над 3X-UI) — сейчас основной бэкенд —
[Marzban](https://github.com/Gozargah/Marzban) с кластером VPN-нод на
VLESS REALITY, и именно этот путь описан в README ниже.

Поддержка 3X-UI как более простого одиночного варианта осталась (см. в
конце), но новые инфраструктурные фичи (ноды, REALITY-тюнинг, авторазвёртывание)
пишутся только под Marzban.

---

## Что это, если коротко

- **Клиенту** — Telegram-бот: купить/продлить подписку, увидеть статус,
  получить ссылку, пройти мастер настройки приложения, почитать FAQ.
- **Админу** — тоже Telegram-бот: подтверждать заявки, управлять клиентами,
  добавлять/переименовывать/чинить VPN-серверы, крутить настройки
  DPI-маскировки, обновлять xray на нодах — всё кнопками, без SSH и без
  веб-панели на каждый день.
- **Под капотом** — Marzban держит базу клиентов и раздаёт им конфиг, ноды
  реально возят трафик (VLESS+REALITY, порт 443), Caddy отдаёт
  дашборд/подписку по двум разным доменам так, чтобы блокировка одного не
  роняла другой.

## Архитектура

```
                      Telegram
                         │
                    ┌────┴────┐
                    │   Бот   │  aiogram, long-polling (входящих портов не держит*)
                    └────┬────┘
                         │ REST API (админ-креды Marzban)
                         ▼
              ┌──────────────────────┐        Caddy :443
              │   Мастер-панель       │◄───┬── mon.домен  (дашборд, за Cloudflare)
              │   (Marzban, «мозг»)   │    └── sub.домен  (подписка, DNS-only, мимо CF)
              │  трафик НЕ возит      │
              └──────────┬────────────┘
                         │ mTLS control-канал (панель ↔ нода)
             ┌───────────┼───────────┐
             ▼           ▼           ▼
          Нода 1       Нода 2      Нода N   ← «cattle»: одноразовые,
       xray-core     xray-core   xray-core    взаимозаменяемые, разворачиваются
       VLESS REALITY :443 — сюда идёт реальный трафик клиентов, напрямую по IP
```

`*` — единственное осознанное исключение: `NODE_PROVISION_ENABLED=true`
открывает у бота один HTTP-порт для выдачи cert новым нодам (см. ниже).

**Почему два домена.** `sub.` (выдача ссылки-подписки) специально не проксируется
через Cloudflare — в отличие от `mon.` (дашборд), это защита от блокировки
CF-диапазонов конкретно у части операторов РФ. Подробности и вся история
инцидента — [`panel/README.md`](panel/README.md).

**Почему ноды одноразовые.** REALITY сам по себе довольно устойчив к DPI, но
если конкретный IP/SNI всё же поймали — проще выкинуть ноду и поднять новую
(минуты, кнопкой в боте), чем чинить старую. Вся инфраструктура вокруг этого
и построена: авторазвёртывание, удалённый апгрейд xray-core, ротация SNI/ключей.

## Что умеет бот

### Клиенту
- 🛒 Купить / 🔁 Продлить — заявка администратору, подтверждение одной кнопкой
- 📊 Моя подписка — статус, срок, ссылка
- 📲 Мастер настройки в 3 шага — установка Happ → импорт подписки → обязательный
  Fragment/Noise (без этого шага VPN в РФ иногда работает нестабильно)
- ⚠️ Подписка не подгружается? — фолбэк на сырые ключи, если сама ссылка
  недоступна оператору (VPN-туннель при этом обычно не затронут — идёт
  напрямую на IP ноды, а не через заблокированный домен)
- ❓ FAQ — DPI, какие приложения работают, пропажа Happ из App Store и т.д.
- 🔑 У меня уже есть подписка — привязать выданную вручную ссылку к своему Telegram
- 💬 Связаться — сообщение админу прямо из бота

### Админу (всё в Telegram)
- 📋 Заявки, 👥 Клиенты (карточка: продлить/выключить/удалить, ручная подпись
  и заметка, привязка tg_id, безлимит)
- 🌍 Серверы — список нод как их видит клиент, переименование, свой SNI и
  Fragment на конкретную ноду, TLS-фингерпринт
- 🛡 Соединение — сменить SNI-камуфляж на весь кластер (с поиском кандидатов
  через сканер TLS1.3-сайтов), перегенерить REALITY-ключи/shortId
- 🖥 Добавить сервер — авторазвёртывание новой ноды по одноразовому токену,
  без ручного SSH и без передачи пароля панели
- 🔄 Обновить xray на всех нодах — по SSH, без захода на каждую руками
- 💳 Цена/реквизиты, 📢 Рассылка, 💾 Бэкап БД в Cloudflare R2 (с опциональным
  age-шифрованием)

## Установка с нуля

Рассчитано на то, что до этого вы Marzban не разворачивали. Нужны:
**2+ VPS** (1 мастер + минимум 1 нода) и **1 домен** с двумя поддоменами.

### 1. Домены

В DNS вашего домена заведите два A-поддомена на IP мастер-сервера:
- `mon.ваш-домен.tld` — дашборд. Cloudflare **Proxied** (оранжевое облако).
- `sub.ваш-домен.tld` — выдача подписки. Cloudflare **DNS only** (серое облако)
  — это принципиально, см. «Почему два домена» выше.

### 2. Клонируйте репозиторий на мастер-сервер

```bash
git clone https://github.com/ВАШ_ЛОГИН/3xui-client-bot
cd 3xui-client-bot
```

### 3. Поднимите Marzban (мастер-панель)

```bash
mkdir -p /opt/marzban && cp panel/Dockerfile panel/docker-compose.yml /opt/marzban/
# docker-compose.yml требует env_file — Marzban стартует на дефолтах почти
# везде, КРОМЕ XRAY_JSON: его дефолт относительный (./xray_config.json),
# мимо смонтированного тома /var/lib/marzban — конфиг REALITY потеряется
# при пересоздании контейнера, если не задать явно.
echo 'XRAY_JSON = "/var/lib/marzban/xray_config.json"' > /opt/marzban/.env
cd /opt/marzban && docker compose build && docker compose up -d
```
Дождитесь, пока контейнер поднимется, затем создайте sudo-админа (спросит пароль):
```bash
docker exec -it marzban-marzban-1 marzban-cli admin create -u admin --sudo
```
Логин/пароль отсюда — то, что дальше попросит `deploy.sh` бота.
Подробности образа (какие патчи и зачем) — [`panel/README.md`](panel/README.md).

### 4. Заведите REALITY-инбаунд (один раз, руками)

Зайдите в дашборд Marzban (`https://mon.ваш-домен.tld/dashboard/` — путь
дефолтный, до `randomize_paths.sh` из шага 8) → **Core Settings** → вставьте
и сохраните:
```json
{
  "log": { "loglevel": "warning" },
  "routing": { "rules": [{ "ip": ["geoip:private"], "outboundTag": "BLOCK", "type": "field" }] },
  "inbounds": [
    {
      "tag": "VLESS REALITY",
      "listen": "0.0.0.0",
      "port": 443,
      "protocol": "vless",
      "settings": { "clients": [], "decryption": "none" },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",
        "realitySettings": {
          "show": false,
          "dest": "dl.google.com:443",
          "xver": 0,
          "serverNames": ["dl.google.com"],
          "privateKey": "PLACEHOLDER_REGENERATE_VIA_BOT",
          "shortIds": ["aaaaaaaa"],
          "publicKey": "PLACEHOLDER_REGENERATE_VIA_BOT"
        }
      },
      "sniffing": { "enabled": true, "destOverride": ["http", "tls", "quic"] }
    }
  ],
  "outbounds": [
    { "protocol": "freedom", "tag": "DIRECT" },
    { "protocol": "blackhole", "tag": "BLOCK" }
  ]
}
```
Ключи-плейсхолдеры реальными делать не нужно — как только бот будет
развёрнут (шаг 7), сразу зайдите в **🛡 Соединение → Перегенерить ключи**,
он сам сгенерирует настоящую X25519-пару. Руками x25519 никто не считает.

### 5. Настройте Caddy (фронт для mon./sub.)

```bash
scp -r panel/caddy root@мастер:/root/caddy-setup
ssh root@мастер 'MON_DOMAIN=mon.ваш-домен.tld SUB_DOMAIN=sub.ваш-домен.tld /root/caddy-setup/setup.sh'
```
Один идемпотентный скрипт: ставит Caddy, получает Let's Encrypt-серт для
`sub.`, настраивает автопродление, переключает Marzban на `127.0.0.1:8001`
(порт 443 отдаёт Caddy). Подробности и разбор частых проблем —
[`panel/caddy/README.md`](panel/caddy/README.md).

### 6. Разверните первую ноду

```bash
cd node
PANEL_URL=https://mon.ваш-домен.tld bash bootstrap.sh
```
Спросит логин/пароль от Marzban (те же, что в шаге 3) и IP панели. Ставит
xray-core зафиксированной версии, поднимает mTLS-канал до панели, проверяет
живым REALITY-хендшейком, что всё реально работает — не просто «панель
говорит connected». Подробности — [`node/README.md`](node/README.md).

### 7. Разверните бота

```bash
cd .. && ./deploy.sh
```
Интерактивно спросит всё: токен бота, ваш Telegram ID, бэкенд панели
(выберите **Marzban**), URL/логин/пароль панели — и сам живьём спросит у
панели список инбаундов, чтобы не гадать вслепую. Дальше — включить ли
авторазвёртывание нод, тариф, бэкапы. Полный список переменных с
комментариями — [`.env.example`](.env.example).

### 8. (Рекомендуется) Спрятать пути дашборда/подписки

```bash
bash panel/randomize_paths.sh
```
Дефолтные `/dashboard/` и `/sub/` — узнаваемый паттерн для любого сканера.
Идемпотентно, можно гонять повторно для ротации.

### 9. Добавьте остальные ноды

Через бота: админка → **🖥 Добавить сервер** → IP нового VPS → вставить
готовую команду в SSH-сессию. Пароль от панели никуда не улетает, токен
одноразовый. Либо руками — `node/bootstrap.sh` ещё раз.

Готово. `/start` в Telegram — должно ответить главное меню.

## Обновление

```bash
cd 3xui-client-bot
./deploy.sh
```
`git pull` + пересборка + перезапуск контейнера бота. `data/bot.db` не
трогается. Обновление панели/нод — отдельные процедуры, см. соответствующие
README (`panel/`, `node/`).

## Структура репозитория

```
bot/            сам бот (aiogram) — handlers/, panels/ (абстракция xui|marzban)
panel/          патченный образ Marzban + Caddy-конфиг для mon./sub.
node/           скрипты развёртывания и обслуживания VPN-нод

```

Подробные README есть в каждой директории — этот файл специально не дублирует
детали, а даёт общую карту и порядок действий.

## Безопасность коротко

| Что | Как защищено |
|---|---|
| `.env`, `data/` | `chmod 600`/`700`, в `.gitignore` |
| Пароль панели | не хранится у бота при авторазвёртывании нод — только у вас |
| SSH-доступ бота к нодам | отдельный ключ, единственная задача — удалённый апгрейд xray-core |
| Лимит трафика клиента | нигде не показывается ему самому |
| Админ-команды | жёсткий allowlist по `tg_id` |
| Входящие порты у бота | нет (long-polling), кроме `NODE_PROVISION_ENABLED=true` — см. `node/README.md` |
| Бэкапы в R2 | опциональное age-шифрование, токену — только запись, без удаления |

## 3X-UI (упрощённый вариант, без кластера нод)

Если не нужен мультинод и вся эта инфраструктура — бот умеет работать и с
одиночным [3X-UI](https://github.com/MHSanaei/3x-ui): один VPS, одна панель,
без Caddy/нод/Marzban. `deploy.sh` спросит бэкенд — выберите **3x-ui** и
заполните `XUI_*`/`SUB_URL_TEMPLATE` из `.env.example`. Это исходный, более
простой путь, с которого начинался проект — новые фичи (REALITY-тюнинг,
ноды) на нём не работают, они специфичны для Marzban.

Если у клиента уже был создан вручную в 3X-UI, но без `tgId` — впишите его
Telegram ID в поле `tgId` клиента в панели, бот подхватит по `/start`.
