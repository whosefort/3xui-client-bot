# xui/ — отдельный сервер с 3x-ui (вторая панель)

Для схемы с двумя панелями сразу (`PANELS=marzban,xui` в `.env` бота, см.
`bot/panels/multi.py`): Marzban с нодами — главная, рядом независимый сервер
со своей 3x-ui. Бот выдаёт/продлевает клиента в обеих, клиент получает две
ссылки-подписки.

- `bootstrap.sh` — подготовка свежего VPS под 3x-ui: SSH на 2222 (с учётом
  socket-активации Ubuntu 24.04), UFW в безопасном порядке, опционально порт
  только для диапазонов Cloudflare, установка 3x-ui, BBR. Перенесён из
  рабочих заметок как есть, пока интерактивный — бот его ещё не вызывает.
- `CLOUDFLARE.md` — runbook по VLESS+WS+TLS за Cloudflare на 3x-ui
  (externalProxy, origin-сертификат, «чистый» CF-IP, диагностика) — второй
  транспорт на случай, если REALITY напрямую начнут душить.

После установки панели: в 3x-ui создать API-токен, в `.env` бота заполнить
блок 3X-UI (`XUI_BASE_URL`, `XUI_API_TOKEN`) и `PANELS=marzban,xui`,
перезапустить бота (`./deploy.sh`).

Для независимых именованных панелей используйте XUI_MANAGED_PANELS
(пример в .env.example). Меню **Панели 3x-ui** или команда /xui открывают
панели по отдельности, в том числе при основном бэкенде Marzban.
PANELS=marzban,xui по-прежнему включает зеркалирование подписок.

- [Рабочая схема Bern → Budapest, проверки и откат](BERN-BUDAPEST.md)


## Смешанный режим

Старые подписки остаются на настроенном PANEL_BACKEND/PANELS. Чтобы выдавать
новые подписки на другой 3x-ui, добавьте её в XUI_MANAGED_PANELS с отдельным
токеном и публичным subscription_url. В заявке на новую подписку админ может
выбрать 3x-ui и вход. «Авто» выбирает первый включённый VLESS-вход,
который участвует в подписке. Выбранные панель и ID входа сохраняются перед
созданием профиля. Повтор после таймаута использует ту же цель.

Панель сохраняется за клиентом вместе с привязкой Telegram. Статус,
напоминания, заявка на продление и приглашение используют эту панель.
Существующая привязка к другой панели защищена от случайной замены.
Если на двух панелях совпал голый subId, используйте полную ссылку.
Для выдачи без Telegram ID есть одноразовое приглашение в карточке входа.

## Управление инфраструктурой

- **Ноды** — статус, проверка, включение и отключение, привязка зарегистрированной
  панели или отвязка. Для связи 3x-ui нужны взаимная доступность HTTPS и отдельный
  node-sync токен. Расположение панели за закрытым файрволом может помешать этому
  режиму. Связка выходов Bern → Budapest использует VLESS и не требует
  регистрации Budapest как штатной ноды Bern.
- **Исходящие и тесты** — список, HTTP-проверка средствами 3x-ui, пресеты прямого
  выхода, IPv4 и блокировки. Пресет добавляется в конец списка и оставляет
  прежний выход по умолчанию. В карточке клиента можно назначить существующий
  выход или взять VLESS/REALITY-выход из другой зарегистрированной панели.
- **Вход по пресету** — VLESS RAW/REALITY, фиксированный SNI, ключи X25519 и
  shortId. «Авто» проверяет несколько целей из списка через 3x-ui и выбирает
  первую, прошедшую TLS 1.3, HTTP/2 и проверку сертификата. Выбирается свободный
  в панели порт из диапазона 24443–24462. Доступность порта снаружи зависит от
  файрвола. Существующие входы можно включать и выключать с подтверждением.
  Для VLESS RAW/REALITY можно менять пару dest/SNI по пресету, сохраняя ключи,
  shortId и остальные параметры.

Для новых панелей сверяйте поддерживаемые операции по их API Docs.

## Устройства и резервные копии

В карточке клиента **Устройства и HWID** показывает зарегистрированные устройства
и лимит на выбранной панели. Можно отвязать одно устройство или все устройства
этого клиента с подтверждением. Лимит 0 означает отсутствие ограничения. Устройства
регистрируются по правилам 3x-ui и только в клиентах, которые передают HWID при
обновлении подписки. Глобальные ограничения панели остаются под управлением администратора.

У каждой панели есть кнопка **Резервная копия**. Бот скачивает снимок штатным API,
проверяет SQLite или заголовок PostgreSQL-архива, шифрует его age и отправляет в R2
по пути backups/дата/xui/идентификатор-панели/. В меню показывается время последней
успешной отправки. Те же снимки входят в ежедневный запуск при BACKUP_ENABLED.
Для снимков удалённых 3x-ui нужен настроенный R2 и BACKUP_AGE_PUBKEY. Без шифрования
бот такие снимки не отправляет. Режим сохранения текущего Marzban не изменён.

На установленной 3x-ui Bern полная запись параметров клиента нужна даже при
точечной привязке или продлении. Адаптер сохраняет срок, квоту, Telegram ID,
HWID-лимит и flow. Для сброса трафика сначала используется текущий Clients API,
устаревший метод по инбаунду остаётся запасным для панелей, отвечающих HTTP 404.
